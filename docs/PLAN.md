# 交付与验收

本项目从空仓库开始，实现用户自行提供 Jev API key 的 Chrome Manifest V3 扩展。完成态是可加载的安装目录、可重现的构建与测试、无私人数据的源码，以及按模块推送的 Git 提交。

## 第一版

- 用户在扩展中保存自己的 API key 和自然语言账号方向，之后可修改或清除。
- 打开扩展后主动点击「检查当前页」，才提取正文或选中文字并发送请求。打开设置、切换标签和浏览网页不触发 API。
- 同一次 Jev 请求评估主题、受众价值、表达风格、目标边界冲突和上下文充分性；应用根据明确规则显示适合转发、建议复核或不建议。
- 不伪造模型解释：判断依据来自各维度的概率与本地规则，不生成原文没有的事实。不会自动转发。
- Key 留在浏览器本地扩展存储，不同步、不进入页面脚本、不写入日志、源码或示例。请求仅发送必要文本和站点来源，不发送 URL 路径、查询参数、片段或表单值。
- 页面文本只存在请求期间的内存中；会话存储仅保留最近结果与有限摘要，重启浏览器后清除。
- 独立的核心判断、HTTP 客户端、浏览器适配器和 UI。先交付 Chrome，Edge 可复用 Chromium 构建；Firefox/Safari 的适配边界写入架构说明，不宣称已验证支持。

## 验收标准

- [ ] Key 与方向能保存、更新、清除；未配置时不会发送请求。
- [ ] 当前页正文或有效选区可被检查；受限页、空内容和动态页面缺失有明确反馈。
- [ ] 成功、复核、不适合、认证失败、限流、超时及响应格式错误均有明确状态。
- [ ] 重复点击不会产生并发重复请求；关闭弹窗后能恢复会话结果。
- [ ] 核心测试、构建、扩展浏览器回归及公开发布隐私扫描通过。
- [ ] README、隐私说明、跨浏览器方案、验证记录可供陌生贡献者复现。
- [ ] 按模块提交并推送到已配置远端；提交身份使用公开用户名及 GitHub noreply 邮箱。

## 边界与假设

第一版是文本判断，不做 OCR、视频理解、外部事实核查、发布授权判断或自动转发。模型概率和产品阈值需要后续用账号样本校准。真实 Jev 请求需要用户在扩展中自行填入 Key；不要求将 Key 提供给开发者或写入仓库。公开就绪不等于自动变更远端仓库可见性，也不包含 Chrome 商店上架。
